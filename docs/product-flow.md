# KillApps 产品流程

## 默认状态

- Android 8.0+，包名 `com.android.killapps`，MD3 明暗主题。
- 停止方式：自动，优先已授权的 root。
- 用户应用开启、系统应用关闭。
- 白名单模式，初始名单为空。所有符合条件的候选默认选中。
- 语言跟随系统：中文使用中文资源，其他语言回退英文；设置可强制选择中文或 English。

## 1. 首次启动与授权

后台执行 `su -c id`，root 管理器可能显示授权请求；拒绝、不存在或超时均视为不可用，不阻塞 UI。首次启动显示授权面板，解释使用情况与辅助功能各自的用途。用户点击辅助功能入口时先显示读取范围及自动点击用途说明，再跳转系统设置。返回后重新检测授权状态。检测到已开启的权限被撤销时再次显示面板。

root 可用时不强迫用户开启无用的辅助功能权限：root 能直接查看进程并停止应用。无 root 路径需要使用情况权限与已连接的辅助功能服务，缺失时无法开始，进入授权面板。

## 2. 候选列表

root 路径以进程 UID、进程包名及 PackageManager 已安装应用建立候选，覆盖没有桌面入口的应用、子进程及共享 UID。仅操作当前 Android 用户，不跨用户关闭应用。强行停止标记已设置的应用不再作为活动候选。

辅助功能路径列出最近 24 小时有活动且未标记强行停止的应用。明确显示“估算候选”：Android 不开放非特权应用完整的运行进程清单，近期活动不等于仍在运行。点击来源说明可以查看这个限制。

候选按用户／系统筛选展示，支持名称与包名搜索。搜索只改变展示，不改变任务选择；开始按钮上方始终显示总选择数量。刷新保留本次取消勾选。首页勾选只影响本次会话，黑白名单作为长期规则保存。

## 3. 筛选规则

按以下顺序计算：当前活动候选 → 用户／系统类型 → 核心保护 → 名单模式 → 本次勾选。

| 模式 | 名单里的应用 | 名单外的应用 |
| --- | --- | --- |
| 白名单 | 保留 | 符合其他条件时可停止 |
| 黑名单 | 符合其他条件时可停止 | 保留 |

名单在全部已安装应用中编辑，名称和包名可搜索、立即保存；两份名单独立，切换模式不清空。空黑名单不会停止任何应用。保护规则始终优先，受保护项无法勾选。

保护自身、低于应用 UID 范围的进程、系统界面、设置、权限安装组件、当前桌面和输入法、默认拨号器、已启用辅助功能服务、设备管理器、常见 root 管理器与这些应用共享 UID 的应用。系统应用开关不覆盖保护规则。

## 4. 点击开始

首先检查必需权限与选中数量。弹窗显示数量、名单模式和实际停止方式，并说明停止可能中断通知。确认后重新检测 root 与活动应用，只处理确认时所选包名与最新候选的交集，不把新出现的应用自动加入。没有符合条件的目标则结束准备并说明原因。

任务快照建立后禁止更改停止方式、名单、类型筛选；不会重复启动任务。

## 5. 逐个停止

- 自动：优先 root，否则辅助功能。
- 仅 root：没有 root 时提示授权，不切换。
- 仅辅助功能：即使存在 root，也使用系统应用详情页。

root 使用 `am force-stop --user <当前用户> <包名>`，每条命令超时 12 秒；验证 PackageManager 的 `FLAG_STOPPED` 后才计成功。标准 Android 不存在 `pm kill`；`am kill` 仅能杀可安全关闭的后台进程，不等价于 Force stop，因此这里选择 `am force-stop`。

辅助功能每个应用依次：打开详情 → 验证为系统 Settings 窗口并找到当前应用标识 → 点击“强行停止” → 找到停止警告与系统确认按钮 → 点击确认 → 验证停止标记。中英系统文案均支持，单项超时 10 秒。窗口不匹配、不可点击或无法验证均记失败，不误报成功。单个失败不终止整个队列，不在任务中途更换后端。

## 6. 取消与结果

root 取消后让当前命令结束，不开始下一项；辅助功能取消后停止后续点击和队列。首页显示处理进度和成功／失败／跳过数量。辅助功能结束后返回 KillApps。任务结果可在右上角菜单或设置查看，包含包名与失败原因。当前版本任务记录存于进程内存，重新启动进程后清空，长期名单和设置持久保存。

## 边界

不会安装包管理特权、绕过系统授权或提供跨用户控制。ROM 改变设置结构或使用非中英的系统文案可能导致辅助功能失败，失败原因会显示，后续可增加 ROM 适配。强行停止不保证系统服务永不重启，也不保证释放固定数量的内存。
